Explanation for the Mesh Game

2026-04-08

This post explains the mesh game. More features are to come for the game. I will also add a background section for those new to the subject. For now this is an early Claude coded prototype to build intuition for how sparse matrices evolve when nodes are removed from their mesh.

Purpose of the game

Playing the game is supposed to help the user develop intuition between meshes and their representative connectivity matrices. In computational science, we develop algorithms (tricks) to solve \(Ax = b\) as quickly as possible. When a matrix is sparse (many of its entries are zero), then we have a basket of tricks to pull from to accelerate the solve. If possible, we would like to shrink these matrices to save on memory. In the "3x3 Grid" example, if one removes node 5, the number of nonzero (nnz) values increases from 24 to 28. This is because information was flowing through 5 from nodes 2, 4, 6, and 8 to nodes 2, 4, 6, and 8. Without 5, we have to draw new connections (edges) in the mesh and update the grid so that the information may still be communicated. In a 3D or more complex setting, removals like this would be devastating for memory. However removing node 1, or any of the corner nodes for that matter, will decrease the nnz values. Information between nodes 2 and 4 flowed through 1, so, in the symmetric connectivity matrix, we dropped two edges for 1. Removals like this are beneficial.

Future work

The long term goal is to develop this into a game where the user strategizes to reduce nnz values.
